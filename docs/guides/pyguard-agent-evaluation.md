# PyGuard agent contract and parity

PyGuard shares Tsguard's Go result module: a schema-1 envelope with findings, measurements, artifacts and diagnostics; `--output json`; bounded agent output (ten findings, omission count, 26 lines / 6 KiB); stable IDs and execution categories; strict input validation and `--root`; and truthful criticality results.

CI requires all 16 behavior cases and all 26 parity cases to pass (see [capability evals](oxguard-evals.md)). Adapter limits are in the [Python result contract](pyguard-result-contract.md). Maintainability parity with Tsguard is tracked in [#23](https://github.com/oxalc88/oxguard/issues/23); the `quality.cognitive_complexity` capability runs complexipy 8.3.0 through `pyguard radon` and verifies that the advisory warning above 20 never changes the exit code or the gate/overall pass–fail outcome. `structure.runtime_graph` runs the advisory `pyguard structure` module graph built with grimp 3.18 and NetworkX 3.7: runtime SCCs and self-loops report `pyguard.structure.CIRCULAR_DEPENDENCY` without changing the exit code or blocking outcome (like Tsguard, an otherwise passing status becomes `advisory`), nested and namespace package identities are preserved, namespace-relative imports resolve, duplicate identities remain non-crashing incomplete evidence, acyclic SCC-condensation depth is exact, and configured-directory/test-file exclusions keep the module count precise. `structure.false_positive_controls` verifies `TYPE_CHECKING`-only imports, external imports and external-name collisions, deferred function-local imports, excluded and narrowed-scope boundaries, genuine package exports, default-scope `src`-layout cycles, narrowed-scope missing children and unresolved/invalid-relative partial assessment. `structure.coupling` verifies per-module fan-in/fan-out and the advisory `pyguard.structure.HIGH_MODULE_COUPLING` warning at the joint 3-importer/8-dependency threshold, with 2/8, 3/7, TYPE_CHECKING-only, deferred, external, configured-exclusion and conventional-test-file controls; the warning never changes the exit code or blocking outcome. `structure.function_graph` verifies the pyan3 2.9.0 function graph through the same command: distinct cross-module callers, uncalled zero, single-caller deduplication, the self-recursion boundary (function fan-in/out exclude a self-call while unchanged `pyguard criticality` in-degree counts it once), Tsguard-parity values, resolved method and nested-function calls, two-function mutual-recursion condensation depth, test-file exclusion, an unresolved dynamic call counted while the assessment stays complete, builtin/import/in-scope resolved calls at zero, local aliases and receiver reads each counted once, a closure parameter attributed only to its nested caller, and unparsable-source `not_evaluated` with an incomplete assessment and exit 0. The function graph emits no findings. `quality.zero_config_exception_handling` runs Ruff S110/B012 through `pyguard ruff`: zero-config projects get blocking pass-only bare/`Exception`/`BaseException` and `finally`-jump findings, typed-exception handlers stay unflagged under Ruff's default `check-typed-exception = false`, and project Ruff configuration, `ignore` entries and native `# noqa` remain authoritative.
