# PyGuard agent contract and parity

PyGuard shares Tsguard's Go result module: a schema-1 envelope with findings, measurements, artifacts and diagnostics; `--output json`; bounded agent output (ten findings, omission count, 26 lines / 6 KiB); stable IDs and execution categories; strict input validation and `--root`; and truthful criticality results.

CI requires all 16 behavior cases and all 26 parity cases to pass (see [capability evals](oxguard-evals.md)). Adapter limits are in the [Python result contract](pyguard-result-contract.md). Maintainability parity with Tsguard is tracked in [#23](https://github.com/oxalc88/oxguard/issues/23); the `quality.cognitive_complexity` capability runs complexipy 8.3.0 through `pyguard radon` and verifies that the advisory warning above 20 never changes the exit code or the gate/overall pass–fail outcome. `quality.zero_config_exception_handling` runs Ruff S110/B012 through `pyguard ruff`: zero-config projects get blocking pass-only bare/`Exception`/`BaseException` and `finally`-jump findings, typed-exception handlers stay unflagged under Ruff's default `check-typed-exception = false`, and project Ruff configuration, `ignore` entries and native `# noqa` remain authoritative.
